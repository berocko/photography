# Valuation Data Packs

Milestone 2 loads server-side valuation rules from every enabled data pack. Rules affect the valuation catalog only; they do not award currency or alter the current camera capture flow.

## Directories

```text
data/<namespace>/photo_values/entities/*.json
data/<namespace>/photo_values/biomes/*.json
data/<namespace>/photo_values/tags/*.json
```

`entities` and `biomes` determine the target registry from the directory. Files in `tags` must add `"object_type": "entity"` or `"biome"`. Every JSON file is an independent resource: a malformed or invalid file is logged and skipped without discarding valid files.

## Fields

```json
{
  "object_type": "entity",
  "selector": "exact",
  "target": "examplemod:ancient_dragon",
  "mode": "override",
  "base_value": 1200,
  "multiplier": 4.0,
  "enabled": true,
  "priority": 10
}
```

- `object_type`: required only in `photo_values/tags`; `entity` or `biome`.
- `selector`: `exact`, `tag`, or `namespace`; default `exact`.
- `target`: an object ID, tag ID without `#`, or namespace according to `selector`.
- `mode`: `override`, `add`, `multiply`, or `disable`; default `override`.
- `base_value`: non-negative integer used by `override` and `add`; default `0`.
- `multiplier`: finite non-negative number used by `multiply`; default `1.0`.
- `enabled`: disabled rule documents are retained as data but do not match; default `true`.
- `priority`: signed integer tie-breaker within one selector level; larger wins; default `0`.

`disable` resolves the object to zero. Addition and multiplication saturate at `Long.MAX_VALUE` instead of overflowing.

## Examples

Exact entity override:

```json
{
  "selector": "exact",
  "target": "minecraft:zombie",
  "mode": "override",
  "base_value": 175,
  "priority": 10
}
```

Entity tag addition through the shared `tags` directory:

```json
{
  "object_type": "entity",
  "selector": "tag",
  "target": "minecraft:skeletons",
  "mode": "add",
  "base_value": 25,
  "priority": 20
}
```

Biome tag multiplication:

```json
{
  "selector": "tag",
  "target": "minecraft:is_overworld",
  "mode": "multiply",
  "multiplier": 1.1
}
```

Namespace addition or multiplication:

```json
{
  "selector": "namespace",
  "target": "examplemod",
  "mode": "add",
  "base_value": 5
}
```

Disable one object:

```json
{
  "selector": "exact",
  "target": "examplemod:decorative_camera_drone",
  "mode": "disable",
  "priority": 100
}
```

## Resolution and validation

Resolution is deterministic:

```text
exact rule > tag rule > namespace rule > runtime observation > automatic value > global default
```

Only the highest-priority matching rule at the winning selector level is applied; rules are not chained. Exact targets must exist in the selected registry. Tag IDs must be valid; an empty/currently absent tag is allowed and can emit an informational diagnostic. Namespace targets must satisfy Minecraft namespace syntax and need not currently have entries.

Typical isolated error:

```text
skipping valuation rule example:photo_values/entities/dragon.json:
Codec: unknown Mode value: mystery
```

## Reload behavior

`/reload` parses resources into a temporary immutable rule set, validates every successful entry, builds a complete replacement catalog, and publishes the snapshot atomically. Readers therefore see either the previous complete catalog or the next complete catalog. Individual bad files are skipped. If resource enumeration or catalog construction fails globally, the previous successful catalog remains active.

Use these administrator commands to inspect results:

```text
/camerapture valuation status
/camerapture valuation entity <id>
/camerapture valuation biome <id>
/camerapture valuation rebuild
/camerapture valuation dump
/camerapture valuation observations reset
```

The entity and biome arguments provide registry ID completion. Dumps are generated by the server under `world/camerapture/debug/`; clients cannot provide paths.
